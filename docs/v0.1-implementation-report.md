## 3. Arquitetura implementada

A base freestanding, Limine, linker higher half, terminal, serial, logger,
formatter, mapa físico e stack de 64 KiB foram preservados. Acrescentados:
GDT/TSS/IDT, diagnóstico, PIC/PIT, input e shell de kernel. Continua BSP único,
ring 0, sem libc, malloc, VMM, scheduler ou dependências Linux em runtime.
[Arquitetura completa](architecture.md).

## 4. GDT layout

| Seletor | Entrada |
| --- | --- |
| 0x00 | Null |
| 0x08 | Código kernel DPL0, L=1/D=0 |
| 0x10 | Dados kernel DPL0, L=0 |
| 0x18 / 0x20 | Reservados, não presentes, para futuro user mode |
| 0x28 / 0x30 | Descritor TSS64 de 16 bytes |

GDT de 56 bytes, limite 55. TSS de 104 bytes, iomap_base=104; RSP0 não usado.
Três stacks IST de 16 KiB para Double Fault, NMI e Machine Check.
LGDT, retorno far, segmentos e LTR em NASM. GDT própria e CS=8 observados no QEMU.

## 5. IDT layout

256 gates de 16 bytes; limite 4095 observado no QEMU. Offset low/middle/high,
selector=8, IST, attributes=0x8e, reserved=0. Todos presentes, DPL0; vetores
críticos usam IST. Demais entradas têm stubs válidos e handler seguro.

## 6. Exception frame

176 bytes: r15–r8, rbp, rdi, rsi, rdx, rcx, rbx, rax, vector, error_code,
rip, cs, rflags, rsp, ss. Preserva 15 GPRs, normaliza erro, limpa DF, alinha
RSP em 16 bytes antes de CALL e retorna por IRETQ. SS:RSP está sempre no frame
deste modo 64-bit, inclusive CPL0; não se aplica a código 32-bit.
[Offsets e referência Intel/AMD](interrupts.md).

Exceções fatais escrevem o dump completo primeiro na serial, depois tentam o
framebuffer; há guarda de recursão e CLI/HLT permanente. PF lê CR2 e decodifica
P, W/R, U/S, RSVD e I/D. Nenhuma falha fatal é executada no boot normal.

## 7. IRQ mapping

| IRQ/vetor | Estado |
| --- | --- |
| CPU 0–31 | Exceções nomeadas |
| IRQ0 → 32 | PIT desmascarado |
| IRQ1 → 33 | PS/2 desmascarado após inicialização |
| IRQ2 → 34 | Cascade fechado enquanto slave mascarado |
| IRQ3–15 → 35–47 | Mascarados, sem drivers |
| Vetores 48–255 | Handler default fatal |

PIC8259 remapeado para 0x20/0x28. EOI no slave antes do master; IRQ7/15
espúrias verificam ISR. IRQ real sem driver é mascarada. APIC permanece futuro.

## 8. PIT configuration

Canal 0, modo 2, comando 0x34, divisor 11932, clock nominal 1193182 Hz.
Alvo 100 Hz; taxa calculada aproximadamente 99,99849 Hz. Contador uint64
monotônico saturante, snapshot com IF preservado. IRQ0 não imprime.
Uptime usa conversão nominal; pode perder ticks durante longos períodos IF=0.

No boot final, duas leituras GDB observaram **2 → 63 ticks**, separadas por
0,6 segundo. Isso exercitou IRQ de hardware, PIC, IDT, EOI e retorno.

## 9. Keyboard implementation

i8042 com tradução desligada, teclado set 1 explícito, consulta do set,
ACK/RESEND e espera limitada. IRQ1 lê status/dado e enfileira; filtra AUX/erros.
Fila de 128 posições, 127 úteis, descarte/reset em overflow. Decoder fora da
ISR suporta ASCII US, ambos Shift, Caps Lock, E0/Pause.
Inicialização observada no boot; caracteres reais via IRQ1 **pendentes**.
[Contrato e limites](keyboard.md).

## 10. Shell commands

help, clear, version, sysinfo, mem, uptime, echo, halt e fault ud2|div0|pf.
Parser próprio; até 127 caracteres, limitado a 121 na tela de 128 colunas.
Backspace preserva prompt. Excesso de input é ignorado. Não há reboot fictício.
Versão central em version.h; nome da ISO deriva dela.
Comandos exercitados em host com dependências simuladas; prompt observado no
guest. Despacho por digitação PS/2 em QEMU não foi executado.

## 17. Problemas encontrados

- Desktop sem Git; repositório real no WSL.
- Sandbox Windows/WSL exigiu escalonamento para executar ferramentas.
- Flag NASM relativa duplicada e tabela absoluta gerando reloc-abs-qword.
- Wrapper PowerShell/WSL com BOM/CRLF e quoting incorreto.
- GDB single-step numa CPU já halted terminou em timeout sem gerar UD2.
- Primeiro harness host de halt repetiu comando após longjmp.
- Pipe de documentação perdeu acentos; extração inicial da versão gerou
  warning awk. São falhas auxiliares corrigidas, não testes aprovados.

## 18. Correções realizadas

Git real preservado, flag deduplicada e tabela de stubs convertida para
offsets signed32 relativos na própria .text, sem relaxar warnings.
Wrappers passaram a usar argumentos estruturados/Python. GDB intercepta antes
de HLT com VM inicialmente pausada. Harness de halt reinicia explicitamente
após noreturn. Documentação regravada UTF-8/LF; awk compara nome da macro.

Falha GDB original preservada no arquivo incremental; C2 e probes finais
passaram. Nenhum triple fault, reset ou corrupção de stack foi observado
nos boots finais. Cenários não executados continuam sem comprovação.

## 19. Limitações conhecidas

Single BSP/ring0; sem SMP, PMM/VMM, guard pages, scheduler, contexto FPU/SIMD
ou recuperação de exceções. IST de DF/NMI/MC implementada mas não provocada
em QEMU. Existe janela inicial antes da IDT própria. Fluxo normal ainda faz
panic se não há framebuffer suportado; diagnóstico emergencial possui
caminho serial independente, sem comprovação de boot sem framebuffer.

Input US/ASCII, sem USB, mouse, ABNT2, LEDs ou histórico. Terminal limpa ao
transbordar, sem scroll. Shell de linha única, sem aspas/pipes/processos.
Uptime nominal; probe PF depende do mapping Limine atual. Sem reboot,
validação UEFI ou hardware físico nesta sessão.

## 20. Itens que dependem de validação manual

**PENDENTE DE VALIDAÇÃO MANUAL**, conforme solicitação explícita do usuário:

- Entrega de IRQ1 e caracteres reais pelo teclado PS/2.
- Digitação, Shift, Enter, Backspace e comandos no guest.
- help/version/sysinfo/clear através do fluxo de input real.
- Renderização, apagamento e dump visível no framebuffer.
- halt acionado por comando digitado; seu despacho foi testado em host,
  e o halt da CPU foi observado pelos probes fatais.

Não foi aberta interface gráfica nem executada a suite PS/2 preparada.
O marco não é declarado integralmente concluído enquanto esses critérios
estiverem pendentes. A criação de v0.1.0 fica reservada ao usuário.

## 21. Próximo milestone recomendado

Concluir o aceite manual e criar o tag após revisão. Depois iniciar PMM com
bitmap de frames, reservas explícitas e testes de ownership; seguir com VMM,
page tables próprias e guard pages. ACPI/MADT/APIC pode avançar antes de SMP.
Não antecipar ring3/heap sem estabelecer essas bases.
